## 0. 用户是谁、要什么（最重要）

- 用户自己焊板子，**只焊直插件，不要贴片**。库里所有"上板"的元器件都必须是直插（THT）。模块自身带贴片没关系，因为它整块插在排母上。
- 这个库用于以后接硬件开发项目。硬件一旦打板就很难改，所以选型和封装不能出错。库要能快速选型、快速算成本、提前查出错误。除了封装和符号，还要做到：
  1. **价格准**：误差控制在 ±5% 左右，标明来源、数量档位和核实日期（第 3 节）；
  2. **知道热度**：哪些料销量高、通用、大众，哪些冷门（第 3 节）；
  3. **有更好的替代**：同功能、更好买、更便宜或更好焊的替代料（第 3 节）；
  4. **一选全带**：在 KiCad 里选一个条目，型号、封装、C 编号、价格全部跟着带上，不会配错封装（第 4 节）；
  5. **画图前查冲突**：I2C 地址、电平、主控引脚限制、电流预算，都能自动查出来（第 5 节）；
  6. **快速算成本、出采购单**（第 6 节）；
  7. **按功能快速选型**（第 7 节）。
- 用户不做细节复核。所有核对由 AI 自己完成，不要把核查工作推给用户。回复用简洁中文。

## 3. 新要求二：市场核查（价格、热度、替代）

每个条目（包括以后新增的）都要补下面这些字段。数据单独写在 `src/market.yaml`（按 id 对应），再写一个 `tools/build_market.py`，生成：

- `reports/价格与热度表.md`
- `价格与热度.csv`

也可以把这几个字段并进 `parts.csv`。

| 字段 | 含义 | 要求 |
|---|---|---|
| `price_lcsc` | 立创商城阶梯价，按 1、10、100 个三档 | 用接口取（见第 9 节），写核实日期 |
| `price_taobao_ref` | 淘宝参考单价 | 取销量前 3 到 5 的店铺，记录每家的店名、商品链接、单价、规格（买 1 个或 10 个）、是否包邮，算出中位数 |
| `price_taobao_min` | 淘宝最低可靠价 | 排除明显劣质或销量极低的店 |
| `price_unit_basis` | 价格口径 | 例如"10 只装折单价、不含运费"，口径必须统一 |
| `price_checked` | 核实日期 | |
| `sales_level` | 热度：大众、常用、冷门 | 依据淘宝"已售"或"月销"、立创销量、教程和开源项目里的出现频率，写明依据 |
| `sales_evidence` | 热度依据 | 例如"淘宝前 5 家合计已售 10 万+"。数字要真实，并写来源 |
| `better_alt` | 更好的替代 | 写理由：更便宜、更好焊、更好买、性能更好、3.3 V 直连、有官方库等 |
| `recommend_shop` | 推荐买的店 | 官方旗舰店、优信电子、正点原子、微雪、合宙官方店、乐鑫官方店、WeAct 官方店等，以实际核实为准 |

**精度要求**：用户要求误差 ±5%。

- 立创价格是精确价，直接用。
- 淘宝同一个东西不同店铺能差一倍。所以"参考价"必须写清是哪几家、什么规格、什么数量。不允许只给一个笼统的区间。
- 价格明显异常（比如 0.01 元引流链接）要排除，并说明排除原因。

**淘宝的限制（如实处理）**：

- 淘宝搜索和商品页大多要登录。**不能登录、不能输入账号密码、不能处理验证码**。
- 可以试的公开途径：
  - 搜索引擎收录的商品页；
  - 品牌官网或官方商城；
  - 京东公开价；
  - 1688 公开页；
  - 立创商城本身（很多模块立创也卖，比如 Pico、1602、部分 OLED）。
- 实在取不到淘宝价的，填"淘宝未核（需登录）"，并给出建议的搜索关键词和店铺，留给用户登录后抽查。**不要编数字。**

**目的**：现在画原理图要先选符号、再单独选封装，还是可能配错。改成每个条目一个"原子符号"：选中它，封装、型号、C 编号、价格全部已经填好。

**每个原子符号的做法**：

| 项目 | 要求 |
|---|---|
| 收录范围 | 符号和封装都不是"不适用"的条目，每条一个。不上板的工具（USB-TTL、ST-Link）不收 |
| 名字 | `编号_型号`，例如 `MCU-009_Arduino-Nano`。只用字母、数字、`-`、`_`、`.` |
| 图形和引脚 | 从条目引用的基础符号（KiCad 官方库或 `StudentHW.kicad_sym`）整份复制。基础符号用了 `extends` 的要展开，因为跨库不能 extends。子单元名要改成 `新名字_单元号_样式号` |
| 属性 | Reference（沿用基础符号）、Value（型号；阻容写阻值或容值）、Footprint（必须和 `kicad_footprint` 完全一致）、Datasheet、Description（中文名称和关键参数）、`MPN`、`Manufacturer`、`LCSC`（C 编号；嘉立创相关的 KiCad 插件常用这个字段名）、`StudentHW_ID`、`Level`、`Price_CNY`、`Price_Date`、`Taobao_Keyword`、`Pin1`（一句话说清怎么认 1 脚）。除 Reference 和 Value 外都隐藏 |
| 关键词 | keywords 写类别、中文名、淘宝关键词，方便在 KiCad 里用中文搜到 |
| 3D | 3D 模型由封装带出，符号不用管 |

**阻容这类"系列件"**：现在 RES-001（1kΩ）、RES-002（10kΩ）每条只有一个阻值，画图和算成本都不够用。

- 新建 `src/series.yaml`，按学生项目常用值列出阻值。建议：10Ω、22Ω、47Ω、100Ω、220Ω、330Ω、470Ω、1k、2k、2.2k、4.7k、5.1k、10k、20k、47k、100k、1M，可按实际项目频率增减。瓷片电容同理，例如 22pF、100pF、1nF、10nF、100nF、1µF。
- 每个值都必须在**同一系列**里查到真实的 C 编号、价格和库存（用 `tools/szsearch.py` 或接口）。查不到的值不建。
- 每个值生成一个原子符号，例如 `RES-001_1k`，封装同母条目。

**check_atomic.py 至少查这些**：
1. 条目和原子符号一一对应，不多不少；
2. Footprint、LCSC、MPN 三个属性和 `parts.csv` 完全一致；
3. 原子符号的引脚号、引脚名与基础符号完全一致，引脚号集合与封装焊盘号一致；
4. `kicad-cli sym export svg` 能导出整个库，证明 KiCad 能读；
5. 自测里注入三种错误：封装属性写错、少一个引脚、C 编号写错。每种都必须报出来。

- 怎么把 `StudentHW_Parts` 加进 KiCad 符号库表；
- 规定以后画图优先从 `StudentHW_Parts` 选。库里没有的件才用通用符号，并在 BOM 里标"库外件"。

## 5. 新要求四：兼容性速查（画图前查冲突）

**目的**：电平不匹配、I2C 地址冲突、用了主控不能用的脚、电源带不动，这几类错误最常见，打板后只能飞线或重做。要在画图前就查出来。

**数据**：新建两个文件。每个值都要写出处（规格书页码或官方文档链接）。查不到写"未核"，**不许估**。

`src/electrical.yaml`：按条目编号，覆盖所有模块和芯片类条目。阻容、端子这类可以不填。

| 字段 | 含义 |
|---|---|
| `vcc_range` | 供电电压范围，例如 3.0–5.5 V |
| `logic_v` | 信号电平：3.3 V、5 V，或随供电变化 |
| `io_5v_tolerant` | 输入脚能否承受 5 V |
| `interface` | I2C、SPI、UART、单总线、模拟、数字、PWM 等 |
| `i2c_addr` / `i2c_addr_alt` | 默认地址、可改成的地址，以及怎么改（ADDR 脚、跳线、焊盘） |
| `i2c_pullup` | 模块板上 I2C 上拉的阻值，以及上拉到哪个电压（VCC 还是板载 3.3 V）。从模块原理图核实 |
| `i_typ_ma` / `i_peak_ma` | 典型电流和峰值电流，写明条件（例如 WiFi 发射、舵机堵转、继电器吸合） |
| `supply_capacity_ma` | 只对电源类和主控板填：能对外提供多少电流，写清板载 LDO 型号和余量 |
| `src_ref` | 出处 |

`src/mcu_pins.yaml`：每块主控板逐脚列出：
- GPIO 号；
- 启动脚（strapping）；
- 只能输入的脚；
- 被 Flash 或 PSRAM 占用的脚；
- USB 脚；
- 板载 LED 和按键占用的脚；
- ADC 通道（ESP32 的 ADC2 在开 WiFi 时有限制）；
- 能否承受 5 V（例如 STM32 的 FT 脚）；
- 默认串口日志脚；
- "可以放心用的脚"清单。

出处用乐鑫、ST 的规格书和开发板原理图。

**报告**：`reports/兼容性速查.md`，由脚本从上面两个 yaml 生成，包括：

1. **I2C 地址总表和冲突表**。要核实的典型情况：
   - MPU6050 和 DS3231 都常用 0x68；
   - MAX30102 和 DS3231 模块（ZS-042）板上的 AT24C32 都可能是 0x57；
   - PCF8574A 转接板的地址跳线全改低后是 0x38，和 AHT20 相同。

   每条写出解决办法：改地址脚、分两路 I2C，或者换型号。
2. **I2C 上拉问题**：
   - 模块上拉到 5 V、再接 3.3 V 主控时有风险；
   - 多个模块的上拉并联后，总阻值可能太小。

   给出计算方法和处理办法，例如拆掉多余的上拉电阻、模块改用 3.3 V 供电。
3. **电平兼容表**：每个模块接 3.3 V 主控时能不能直连，需不需要分压或电平转换。例如 HC-SR04 的 Echo 输出 5 V，而 ESP32 的 GPIO 不耐 5 V。
4. **主控引脚约束表**：每块主控板一张，标出能用、慎用、别用的脚。
5. **电流预算参考表**：各模块的电流，以及各种供电方式（USB 口、各稳压器、主控板板载 LDO）能带多少，留 30% 余量。

**项目检查工具** `tools/check_project.py projects/<项目名>.yaml`（项目文件格式见第 6 节）。它要检查：

- I2C 地址冲突（按总线分别查）；
- 电平不匹配：5 V 信号接到不耐 5 V 的脚；
- 用到启动脚、只能输入的脚或被占用的脚，或者同一个脚被分配两次；
- 电流预算：典型值和峰值加起来，超过供电能力的 70% 就报警；
- I2C 上拉：算出并联后的总阻值，并检查上拉到哪个电压；
- 用到贴片件、C 级件（要到货实测）或库外件时给出提醒。

有错误时退出码非 0。

**自测**：准备几份故意出错的样例项目，每种错误都必须报出来；再准备一份干净的样例，必须通过。

**采购量规则**写在 `src/buy_rules.yaml`，可以改：

- 库存低于常用量；
- 价格变化超过 10%；
- 价格核实日期超过 30 天（`project_cost.py` 出成本时也要提示）。

**自测**：
- 用一份手算好的样例项目，`project_cost.py` 算出的总价必须和手算一致；
- 阶梯价选档要有测试；
- 缺价提示要有测试。

只生成文件，**不下单、不加购物车**。

## 8. 每个条目的闭环要求（沿用，已经在第一、二批执行）

- **来源**：标准件要有立创 C 编号，用接口核实型号和厂家一致；模块要有厂家或商品资料，`datasheet_url` 不能空。
- **证据**：
  - `evidence/<id>/datasheet.pdf` 必须有。
  - `dim_*.png` 是尺寸图截图，用 `tools/render_dim.py` 从 PDF 裁剪。
  - 只有图片的 PDF，要在 `dim_source` 里写"人工读图"。
  - 多个条目共用同一张尺寸图时，用 `evidence_extra` 引用。不要把同一张 PNG 复制到多个目录，检查会报错。
- **引脚**：`pinout` 写清每个脚的定义，以及怎么认 1 脚（方焊盘、色环、平边、长短脚、圆点、丝印）。
- **封装**：
  - 能用 KiCad 官方的就引用官方的。
  - 环宽不够时：孔 ≤0.9 时环宽 ≥0.4，孔更大时 ≥0.5。可以自建加大焊盘的封装，或者写 `ring_min_mm`，并在备注里写"环宽"两个字说明原因。
  - 脚距公差 ±0.02。
- **模块封装**：在 `tools/module_defs.py` 里加定义，由 `tools/gen_modules.py` 生成。约定如下：
  - 俯视，1 脚放在 (0,0)；
  - 排针孔 1.0、焊盘 1.7；
  - 丝印画模块外框，引脚名印在外框外；
  - Fab 层画天线等伸出部分和安装孔；
  - 属性 `Module_Height` 记录模块插上后的高度。
- **电气字段（新增）**：从第二批剩余条目开始，模块和芯片类条目还要填第 5 节的 `src/electrical.yaml`，主控板还要填 `src/mcu_pins.yaml` 的逐脚表。前面已入库的条目在第 11 节第 6 步统一补。
- **等级**：
  - A 级只给规范第 7 节打勾的件，引用 V1.1 `Silver.pretty` 的复制件。
  - B 级必须有厂家图纸逐项核对。
  - C 级是没有可靠图纸、要到货实测的件。**不许把 C 级写成 B 级。**
- 做不到闭环的不要留占位行，写进 `待确认.md`。
- 每批完成后写 `reports/batchN_报告.md`，并更新 `README.md`、`待确认.md`、`常用元器件清单.md`（后者由脚本生成）。

## 12. 已知的坑（别再踩）

- 本库文件是 KiCad 10 格式，KiCad 8 和 9 打不开。不要为了能打开而把文件降级。
- 脚距容差 ±0.05 分不出 XH 的 2.50 和 2.54，已经收紧到 ±0.02。
- `kicad-cli` 导出 SVG 前要先建好输出目录，还要加 `--black-and-white`，否则是白底白线。
- Windows 的 `http.server` 会把 SVG 的类型报成 `image/svg`，浏览器显示不出来。看预览要用 `tools/serve.py`。
- 本机 KiCad 官方库缺 PJ-102AH、HRO Type-C、BS-07 的 3D 模型，已经用立创 EDA 的 `.wrl` 模型加偏移解决，渲染核对过。
- 志浩数码管的 PDF 是 GBK 编码乱码，型号在图片里，所以 `dim_source` 写了"人工读图"。
- 模块封装里，同一位置叠放、但脚号不同的焊盘（如 Type-C 的 A1 和 B12），在测试板上要给同一个网络，否则 DRC 报间距错误。`build_testboard.py` 已经处理。
